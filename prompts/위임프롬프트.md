# 위임 프롬프트 카드 (Claude Code / Codex 공통)

좋은 위임 = 역할 · 맥락(AGENTS.md) · **한 단계** · 금지 · 출력 형식 · 완료 조건.

## ① 환경 확인 (T+0)
```
이 작업 환경을 파악만 해 줘. 수정·설치는 하지 마.
OS, python3/node 버전, 설치된 주요 패키지(pip list 상위), 인터넷 연결 가능 여부(curl -sI https://pypi.org 응답 코드만),
현재 폴더 구조(2단계), 데이터 파일별 크기와 행 수를 표로 보고해.
```

## ② 데이터 점검 (분석 금지)
```
AGENTS.md를 먼저 읽어. 이번 단계는 데이터 점검만 한다. 결론·판정 규칙은 만들지 마.
python3 scripts/check_data.py <폴더> --keys <키>를 실행하고, 추가로 <이 과제에 특화된 확인 항목>을 집계해.
출력 원문을 붙이고, 담당자에게 확인할 질문 목록을 만들어.
```

## ③ 가설 검증 (한 번에 하나)
```
가설 H1: "<가설>". 맞다면 데이터에서 보여야 할 것 2개, 틀렸다면 보여야 할 것 2개를 먼저 적어.
그다음 4가지를 확인하는 코드를 실행하고 각각 수치와 함께 지지/반박/불명확으로 판정해.
교란 요인(구성 변화·기간·장비)별로 나눠 본 결과도 보여 줘.
```

## ④ 끝까지 도는 v0
```
가장 단순한 끝까지 동작하는 버전을 만든다. 성능보다 "입력→처리→출력"이 한 줄 명령으로 도는 게 목표.
- 실행: <명령> → <출력/포트>
- 방법: <규칙 하나>. 고급 기법 금지. 임계값은 상수로.
- 테스트: <핵심 경계 조건 3개>
끝나면 실행 로그, 테스트 결과, 내가 직접 읽어야 할 핵심 함수 3개를 파일:줄로 알려 줘.
```

## ⑤ 오류 분석 후 개선
```
현재 결과에서 틀렸거나 의심스러운 사례를 표로 뽑아 줘: id | 결과 | 기대 | 관련 원본 값.
공통 패턴 후보 3개와 각 확인 방법을 제안해. 내가 하나를 고르면 그것만 고친다.
고친 뒤 같은 데이터에서 전후 지표를 나란히 보여 줘.
```

## ⑥ 교차 리뷰 (다른 세션·다른 도구에서)
```
너는 이 저장소를 처음 보는 리뷰어다. AGENTS.md의 성공 기준과 REPORT.md의 주장을 읽고 코드가 그것을 뒷받침하는지 검사해.
누수, 하드코딩, 예외 처리, 문서·코드 불일치, 제약 위반. 심각도·파일:줄·재현 명령. 고치지는 마.
```

## ⑦ 문서·코드 대조 (제출 30분 전)
```
REPORT.md, README.md, HANDOFF.md의 모든 숫자와 주장이 지금 코드 실행 결과와 일치하는지 대조해.
테스트를 다시 실행하고, 불일치 목록만 보여 줘. 문서는 내가 고친다.
```
