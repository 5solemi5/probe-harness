# 위임 프롬프트 카드 (Codex · 웹 서비스형 과제)

좋은 위임 = AGENTS.md 맥락 · **한 단계** · 금지 · 완료 조건 · 보고 형식.
모든 카드 끝에 붙인다: **"끝나면 한 일 / 실행한 명령과 출력 / 남은 의문 3줄로 보고해."**
`< >` 안은 과제에 맞게 바꾼다.

## ① 환경 확인 (시작 직후)
```
수정·설치하지 말고 환경만 파악해 줘. python3/pip/node/docker 버전, docker 동작(docker info 요약),
pypi.org 접속 가능 여부(응답 코드만), 3000 포트 사용 여부, 폴더 구조 2단계, 데이터 파일별 행 수를 표로.
```

## ② 데이터 점검 (구현 금지) — 스킬 `$data-check`
```
AGENTS.md를 먼저 읽어. 이번 단계는 데이터 점검만 한다. <데이터 설명 문서>의 열 정의와 실제 파일을 비교해
열 누락·결측·중복 키·참조 불일치·날짜/시각 형식·허용 값 밖의 값·조합 누락을 집계해.
파일 원문을 길게 출력하지 마. 데이터셋 검증 규칙 후보와 담당자에게 물을 질문을 한 줄씩 만들어.
```

## ③ 끝까지 도는 뼈대 v0 (로직 없이 구조만)
```
AGENTS.md의 스택으로 v0을 만든다. 로직은 비워 두고 구조만:
앱(0.0.0.0:$PORT), 헬스체크(DB 연결 확인), 시작 시 스키마 생성 + 기본 데이터 적용 + 역할별 계정 시드(env),
로그인/로그아웃과 역할 검사, <데이터셋 목록·검증·적용 API>, 화면 <개수>개(빈 골격),
.env.example, Dockerfile, .dockerignore, requirements.txt, 헬스체크 테스트 1개.
완료 조건: 테스트 통과, curl 헬스체크 200, docker build 성공. 직접 실행해서 출력 보여 줘.
```
(골격이 필요하면 `cp -n ~/.h/templates/web/{Dockerfile,.dockerignore,.env.example} .`)

## ⑤ 독립 검증기 (새 세션에서: `/new`)
```
너는 채점자 입장이다. <생성기 파일>은 읽지 마. 과제 지시문의 규칙과 <출력 스키마 문서>만 근거로
검증기를 만든다: 출력 결과 + 원본 데이터 → 위반 목록(규칙 이름, 대상, 기대값, 실제값).
테스트: 정상 예시 1개 + 규칙마다 하나씩 일부러 망가뜨린 결과가 정확히 그 위반으로 잡히는지. CLI로도 실행 가능하게.
```


## ⑧ 교차 리뷰 — 스킬 `$cross-review` 또는 `/review`
```
너는 이 저장소를 처음 보는 리뷰어다. 과제 요구사항과 실행 안내 문서의 주장을 코드가 뒷받침하는지 검사.
비밀값 하드코딩, 권한 누락 API, 롤백 안 되는 경로, 시간대 버그, 비결정성. 심각도 · 파일:줄 · 재현 명령. 고치지는 마.
```

## ⑨ 문서·코드 대조 (제출 25분 전) — 스킬 `$submit-gate`
```
실행 안내 문서와 docs/VERIFICATION.md의 모든 명령을 실제로 실행해 결과가 문서와 같은지 표로 보여 줘.
다르면 문서를 고칠지 코드를 고칠지 나에게 물어. 과제 지시문은 건드리지 마.
```
