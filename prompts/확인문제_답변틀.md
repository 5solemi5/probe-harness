# 확인 문제 답변 틀 (AI 없이 3분, 붙여넣기 불가)

**4문장 공식**: ① 결론 → ② 내 코드의 구체 지점(파일·함수·숫자) → ③ 위험·이유 → ④ 확인·개선 계획.
분량 200~350자. 처음 20초에 구조를 정하고, 2분 30초에 마무리 문장을 쓴다.

| 질문 유형 | ②에 넣을 것 | ④에 넣을 것 |
|---|---|---|
| 핵심 동작과 확인 방법 | 입력→처리→출력 흐름, 핵심 함수 이름 | 테스트 개수·실데이터 수치·담당자 확인 |
| 데이터를 왜 그렇게 처리했나 | 특수값·중복 규칙과 담당자 답 | 처리 안 했을 때의 결과 수치 |
| 기준·임계값 근거 | 기준선 계산법, 숫자, 과거 데이터만 쓴 이유 | 틀릴 수 있는 조건 + 보완책 |
| AI 제안을 고친 부분 | 어떤 출력이 왜 의심스러웠나 | 어떻게 검증했고 무엇이 바뀌었나 |
| 운영 시 약점 | 파일·함수 단위의 약점 | 모니터링·테스트·개선 계획 |
| 담당자 대화가 바꾼 것 | 질문 → 새 사실 → 설계 변경 | 그 결과 숫자 |

약한 답: "데이터 품질 문제가 있을 수 있어 추가 검증이 필요합니다."
강한 답: "임계값을 9월 데이터로만 정했습니다(select_threshold). 제품 구성이 바뀌면 기준선이 움직여 오알람이 늘 수 있어, 주간 알람 수가 합의 기준을 넘으면 경고하는 테스트를 추가하겠습니다."
