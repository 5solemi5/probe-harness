# 후속 질문 대비 (답 작성 금지)

후속 질문은 제출물을 근거로 만들어지고, 사람이 AI 없이 답한다. 이 스킬은 **근거를 모으고 확인만** 한다.

1. 코드, `docs/`(DECISIONS·VERIFICATION·AI_LOG·INTERVIEW), 과제가 요구한 문서(실행 안내·AI 협업 문서), `git log --oneline`을 읽는다.
2. 아래 유형으로 질문 6개를 만든다. 질문은 이 저장소의 실제 파일·기능 이름을 넣어 구체적으로 쓴다.
   1. 핵심 설계 선택: 무엇을 왜 골랐고, 대안과 무엇이 다르며, 무엇을 포기했나
   2. 데이터 흐름: 입력이 화면·내보내기까지 가는 경로와 단계별 실패 책임
   3. 검증 범위: 실제로 검증한 것과 미검증·가정, 다른 사람이 재현하는 방법
   4. 운영 변경·장애: 조건 변경 재계산, 잘못된 데이터 적용, 처리 중 입력 변경 시 정상·실패 경로
   5. 가장 위험한 지점: 어떤 조건에서 제약이 깨지나, 어떤 테스트·규칙으로 확인했나, 추가 개선
   6. AI 협업: AI 협업 문서에 적은 사례의 수용·수정·폐기와 각각의 근거
3. 질문마다 **답에 써야 할 근거만** 목록으로: 파일:함수, 실행 명령, 결과 숫자, 테스트 이름, DECISIONS·AI_LOG 항목 번호. 근거가 없으면 "근거 없음 — 보강 필요"로 적는다.
4. 근거를 하나씩 실제로 확인한다: 명령은 다시 실행하고, 숫자는 방금 출력에서 읽고, 파일:함수는 존재를 확인한다. 표: 근거 | 확인 방법 | 결과 | 일치/불일치.
5. 결과를 `docs/SELF_BRIEF.md` 맨 위에 붙인다. 불일치나 "근거 없음"은 고치지 말고 맨 끝에 "제출 전 보강할 것" 최대 3개로 정리한다.
6. **답 문장을 쓰지 않는다.** 사람에게 "질문마다 결론 → 근거 → 한계 세 줄로 직접 써 보라"고 안내한다.
