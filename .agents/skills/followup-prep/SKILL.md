# 후속 질문 대비

후속 질문은 제출물을 근거로 새로 만들어지고, 사람이 AI 없이 직접 답한다. 그래서 문장을 외우는 것보다 **근거를 기억하는 것**이 목표다.

## 공통 (항상)
1. 코드, `docs/`(DECISIONS·VERIFICATION·AI_LOG·INTERVIEW), 과제가 요구한 문서(실행 안내·AI 협업 문서), `git log --oneline`을 읽는다.
2. 아래 유형으로 질문 6개를 만든다. 이 저장소의 실제 파일·기능 이름을 넣어 구체적으로 쓴다.
   1. 핵심 설계 선택: 무엇을 왜 골랐고, 대안과 무엇이 다르며, 무엇을 포기했나
   2. 데이터 흐름: 입력이 화면·내보내기까지 가는 경로와 단계별 실패 책임
   3. 검증 범위: 실제로 검증한 것과 미검증·가정, 다른 사람이 재현하는 방법
   4. 운영 변경·장애: 조건 변경 재계산, 잘못된 데이터 적용, 처리 중 입력 변경 시 정상·실패 경로
   5. 가장 위험한 지점: 어떤 조건에서 제약이 깨지나, 어떤 테스트·규칙으로 확인했나, 추가 개선
   6. AI 협업: AI 협업 문서에 적은 사례의 수용·수정·폐기와 각각의 근거
3. 질문마다 **근거 목록**: 파일:함수, 실행 명령, 결과 숫자, 테스트 이름, DECISIONS·AI_LOG 항목 번호. 없으면 "근거 없음 — 보강 필요".
4. 근거를 하나씩 실제로 확인한다: 명령은 다시 실행하고, 숫자는 방금 출력에서 읽고, 파일:함수는 존재를 확인한다. 표: 근거 | 확인 방법 | 결과 | 일치/불일치.

## 기본 모드 (`$followup-prep`)
5. 답 문장은 쓰지 않는다. 결과를 `docs/SELF_BRIEF.md` 맨 위에 붙이고, 불일치·"근거 없음"은 맨 끝에 "제출 전 보강할 것" 최대 3개로 정리한다.

## 답안 모드 (`$followup-prep 답안 포함`)
5. 질문마다 **모범 답안 초안**을 쓴다.
   - 구조: ① 결론 한 문장 → ② 근거(파일:함수·명령·숫자) → ③ 한계와 보완. 300자 안팎, 사람이 5분 안에 직접 칠 수 있는 길이.
   - 문장마다 끝에 근거를 괄호로 단다. 예: `(app/validator.py:validate_plan, pytest 12 passed)`.
   - **4단계에서 "일치"로 확인된 근거만** 쓴다. 확인 못 한 내용은 쓰지 않거나 "미검증"이라고 밝힌다.
   - AI 협업 질문(6)은 `docs/AI_LOG.md`에 실제로 있는 줄만 사례로 쓴다. 판정·근거를 지어내지 않는다.
   - 과장 금지: "완벽히", "모든 경우" 같은 표현을 쓰지 않는다.
6. 질문마다 **변형 질문 2개**를 덧붙인다. 같은 근거로 답할 수 있지만 각도가 다른 질문(예: 반대 상황, "왜 X를 안 했나", 재현 방법).
7. 맨 끝에 **외울 핵심 근거 5개**(주요 파일·함수 이름, 테스트 개수, 대표 지표 숫자, 버린 대안)와 "제출 전 보강할 것" 최대 3개.
8. 결과를 `docs/FOLLOWUP_QA.md`에 쓴다. 마지막 줄에 안내: "문장을 외우지 말고, 변형 질문에 근거 5개로 직접 답해 보세요. 실제 서술형은 붙여넣기·AI가 금지됩니다."
