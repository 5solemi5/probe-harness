# 완료 전 검증

완료를 보고하기 전에 아래를 **실제로 실행**하고, 명령과 출력 끝부분을 그대로 보여 준다.

1. 테스트: AGENTS.md "완료 조건"의 테스트 명령. 통과 개수를 적는다.
   - 0개 실행, 전부 skip, import 오류로 수집 실패는 **실패**로 본다.
2. 서버: 새로 띄운 뒤 헬스체크와 바뀐 API를 `curl`로 호출한다. 상태 코드와 응답 앞부분을 보여 준다.
   - 권한이 걸린 API를 바꿨으면 권한 없는 역할로도 호출해 거부되는지 본다.
3. 실패 경로: 바꾼 기능에 잘못된 입력을 하나 넣어 오류가 나고 기존 데이터가 유지되는지 본다.
4. 숫자: 보고하려는 수치를 방금 실행 결과에서 다시 읽는다. 기억이나 이전 출력의 숫자를 쓰지 않는다.
5. 변경 범위: `git diff --stat`으로 의도하지 않은 파일이 바뀌지 않았는지 본다. 과제 지시문이나 원본 데이터가 바뀌었으면 즉시 멈추고 알린다.
6. 확인한 것을 `docs/VERIFICATION.md`에 한 줄 추가한다.

보고 형식 (3줄):
- 한 일:
- 확인한 것 (명령 → 결과):
- 남은 의문·확인 못 한 것:

확인하지 못한 것은 "확인 못 함"이라고 쓴다. 추측으로 채우지 않는다.
