## 절대 규칙 (과제 지시)
- 과제 지시문(루트 `README.md` 등)은 수정·이동·교체하지 않는다.
- 제공된 원본 데이터(`___/`)는 수정하지 않는다. 변형 데이터는 생성 스크립트로 별도 폴더(`___/`)에 만든다.
- 파일 업로드(`<input type=file>`)·파일 선택창·저장창이 금지된 과제면 쓰지 않는다. 데이터는 서버 폴더 목록에서 고르고, 내보내기는 서버가 저장한 뒤 화면에 내용을 보여 준다.
- 외부 API·CDN·외부 지도 금지(과제가 허용하지 않는 한). 계산에 쓰는 값은 제공 데이터에서만 가져온다.
- 설정·비밀값(DB 경로/URL, 초기 비밀번호, 포트, 세션 키)은 환경변수로 받는다. 코드에 값을 직접 쓰지 않는다. `.env.example`만 커밋하고 `.env`는 커밋하지 않는다.
- 서버는 `0.0.0.0:${PORT:-3000}` 에 띄운다. 시간대는 `TZ=___` (예: Asia/Seoul).

## 작업 규칙
- 한 번에 한 단계. 끝나면 3줄 보고: 한 일 / 확인한 것(실행한 명령과 출력) / 남은 의문.
- 큰 데이터 파일을 통째로 출력하지 않는다. `head`, 행 수, 집계만 본다.
- 생성기(결과를 만드는 코드)와 검증기(규칙을 검사하는 코드)는 서로의 코드를 재사용하지 않는다.
- 데이터 적용은 원자적으로: 전부 검증 통과 → 한 트랜잭션으로 교체. 실패하면 기존 데이터·결과를 유지한다.
- 결과에는 데이터 버전과 파라미터를 함께 저장한다. 현재 데이터와 버전이 다르면 "재계산 필요"로 표시한다.
- 새 패키지 설치는 먼저 묻는다.
- "됩니다"라고 쓰기 전에 실제로 실행한다. 수치를 말할 때는 그 수치를 만든 명령을 같이 적는다.
## 기록 규칙 (제출 뒤 후속 질문의 근거 — 매 단계 지킨다)
- 구조·알고리즘·스택·데이터 처리 방식을 정하면 그 자리에서 `docs/DECISIONS.md`에 D항목(결정 / 이유 / 대안 / 포기 / 보완)을 추가한다.
- 테스트나 확인을 실행하면 `docs/VERIFICATION.md`에 한 줄(주장 / 명령 / 결과 숫자 / 검증·부분·미검증)을 추가한다.
- 맡은 작업을 끝내면 3줄 보고 뒤에 `AI_LOG 후보: <맡은 것> / <내놓은 것> / <사람이 판정할 점>` 한 줄을 붙인다. 수용·수정·폐기 판정은 사람이 말한 것만 `docs/AI_LOG.md`에 적는다. 판정을 지어내지 않는다.
- 담당자 답을 전달받으면 `docs/INTERVIEW.md`와 이 파일의 "도메인 사실"에 `[T+분]`으로 반영한다.
- 커밋 메시지는 "무엇을, 왜 + 결과 숫자" 형식으로 쓴다. 단계마다 커밋을 제안한다.
- 문서의 숫자·명령은 실제 실행 결과에서만 가져온다.

## 데이터 흐름과 실패 책임 (DECISIONS.md "흐름" 표로 유지)
- 입력 선택 → 검증 → 적용(저장) → 생성 → 독립 검증 → 결과 저장 → 조회·시각화 → 내보내기.
- 단계마다 담당 파일·함수, 실패하면 무엇을 반환·표시하고 무엇을 유지하는지 적는다. 구조가 바뀌면 표도 고친다.

## 실패 경로 테스트 (해당 기능을 만들 때 함께 작성)
- 잘못된 데이터 적용 → 거부되고 기존 데이터·결과·버전이 그대로다.
- 조건·데이터 변경 뒤 이전 결과 → "재계산 필요"로 표시되고 새 결과처럼 보이지 않는다.
- 권한 없는 역할의 API 호출 → 서버가 거부한다.
- 생성·적용 도중 입력이 바뀌는 경우 → 반쯤 적용된 상태가 남지 않는다(버전 비교 또는 잠금).
- 빈 DB로 재시작 → 정상 기동, 헬스체크 200.
- 테스트 이름을 `docs/VERIFICATION.md`에 적는다.
